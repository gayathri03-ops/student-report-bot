Student Result Query Bot (PRJ-030)
A schema-aware bot that answers marks, attendance, and class-performance queries from a student database — built with FastAPI, Streamlit, and an optional LangChain-powered NLU layer. See docs/architecture.md for the full data-flow diagram and design rationale.

Features
Basic Q&A on results and attendance by register number (Week 1)
Retrieval fallback with citations for freeform questions that don't give a register number directly (Week 2)
Admin refresh workflow to rebuild the DB/index without restarting the server (Week 2)
Role-based access control: students can only see their own result/attendance; admins can see everything, including rankings (Week 3)
Interaction logging for history/audit (Week 3)
Chart output and saved questions in the chat UI
Setup Instructions
Create a virtual environment
bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
Install dependencies
bash
   pip install -r requirements.txt
Build the database (from data/students.csv)
bash
   python -m app.db_setup
Run the backend (terminal 1)
bash
   uvicorn app.main:app --reload
Visit http://127.0.0.1:8000/docs to try the API directly.

Run the chat UI (terminal 2)
bash
   streamlit run streamlit_app.py
(Optional) Enable LLM-assisted parsing/explanation
bash
   export OPENAI_API_KEY=your_key_here   # Windows: set OPENAI_API_KEY=...
Without this, the bot still works fully using rule-based parsing — no API key or internet connection is required for the core features.

"What is the class average in Circuit Theory?"
"Give me the class performance summary"
"Tell me about a student with excellent attendance and marks" (freeform — uses the retrieval fallback and shows a citation)
Access Control
In the Streamlit sidebar, choose Student or Admin:

Student: must enter their own register number; can only view their own result/attendance and class-wide aggregates (not other students' names or rankings).
Admin: can view everything.

Notes for Submission
All data in students.csv is dummy/sample data — no real student records are used, per the assignment's data-privacy requirement.
No API keys or credentials are hardcoded; OPENAI_API_KEY (if used) is read from an environment variable only.
students.db, data/vector_store/, and data/interaction_log.jsonl are generated automatically and are git-ignored — only the source CSV is committed.
Regular, incremental GitHub commits are expected — commit after each file/feature above rather than in one final dump.
